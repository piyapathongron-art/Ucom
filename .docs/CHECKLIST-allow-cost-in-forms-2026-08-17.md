## 5. เช็คระดับฐานข้อมูล (ถ้าอยากดูค่าดิบ)

```bash
/opt/homebrew/opt/libpq/bin/psql "$DATABASE_URL" -c "
select imei, model_name, list_price, sale_price, cost
from device_units where imei = '999999999999999';
select name, price, cost, qty from products where name = 'ทดสอบต้นทุน';"
```

ค่าที่ควรเห็น:
- เครื่อง: `list_price = 6500` · **`sale_price = NULL`** · `cost = 5000`
- สินค้า: `price = 100` · `cost = 70`

> ถ้า `sale_price` ออกมาเป็น `0` แทนที่จะเป็น `NULL` = แก้ไม่ติด กลับไปดูข้อ 1.3

## สรุปสิ่งที่ผมยืนยันไปแล้ว vs ที่ยังไม่ได้ยืนยัน

**ยืนยันแล้ว (ระดับ SQL/prod จริง):**
- migration apply เข้า prod สำเร็จ · signature ยังเป็น `payload jsonb` ตัวเดียว ไม่เกิด overload ซ้อน
- dump `prosrc` กลับมาเทียบแล้ว: UPDATE branch ของทั้งสอง RPC **ไม่มี `cost`** เลย · INSERT branch มีครบ
- พิสูจน์บั๊ก `sale_price = 0 → coalesce = 0` ด้วย query จริงบน prod แล้ว
- `tsc --noEmit` และ `eslint` ผ่านสะอาด

**ยังไม่ได้ยืนยัน:**
- ทุกข้อในเช็คลิสต์นี้ — ยังไม่เคยรันผ่าน UI จริงสักครั้ง
