# 0017 — เครื่อง SF ออกจากสต็อกได้แค่ 2 ทาง ไม่มีวันครบกำหนด

- **สถานะ:** ตัดสินใจแล้ว
- **วันที่:** 2026-08-16

## บริบท

ADR 0002 อธิบายไว้ 3 ทาง ("ลูกค้ามาผ่อนทัน", "ไม่มีใครผ่อนจนเลยกำหนด", "จ่ายเต็มไปแล้วค่อยมีคนผ่อน")
โดยอิง `sf_orders.due_date` เป็นตัวจุดชนวนทางที่สอง เจ้าของร้านยืนยันว่าในทางปฏิบัติ**ไม่มีวันครบกำหนดที่บังคับ
อะไรเลย** — ร้านรับเครื่องมาจาก SF แล้วมีทางออกแค่ 2 ทาง เลือกได้ทุกเมื่อ:

1. **ผ่อน SF** — ลูกค้าทำสัญญากับ SF (ADR 0002/0016 ยังใช้ได้เต็มที่)
2. **ขายสดปกติ** — ร้านจ่ายเงินคืน SF เต็มราคาป้าย แล้วขายให้ลูกค้าในราคาของร้านเอง เหมือนเครื่องซื้อขาดทั่วไป

ปัญหาที่พบจากโค้ดจริง: `device_units.list_price` ถูกใช้เป็นทั้ง "หนี้ต่อ SF" และ "ราคาขาย" ในเวลาเดียวกัน —
`v_pos_catalog`/`v_pos_stock` เอา `list_price` ไปโชว์เป็นราคาขายตรงๆ และ `rpc_create_sale` ใช้
`coalesce(d.cost, 0)` ซึ่งเครื่อง `sf_credit` มี `cost = null` เสมอ (ยังไม่จ่าย SF) → ขายสดเครื่อง SF แล้ว
ต้นทุนลงเป็น 0 กำไรเพี้ยนเต็มจำนวนราคาขาย และไม่มีที่ให้ตั้งราคาขายที่ต่างจากราคาป้ายเลย

`sf_orders.due_date`, `v_sf_due.days_left`, `device_units.sf_paid_full_at` ทั้งหมดตั้งอยู่บนสมมติฐานวันครบ
กำหนดที่ไม่มีจริง — `sf_paid_full_at` เป็น dead column ตั้งแต่สร้างมา ไม่มี RPC/trigger ไหนเขียนมันเลย

## ทางเลือกที่ชั่ง

1. **ยัดราคาขายลง `cost` ตั้งแต่รับเข้า** (ตอนตั้งราคาขาย ก็ set cost = list_price ไปเลย) — ตกเพราะ
   `cost is null` เป็นสัญญาณ "ยังไม่จ่าย SF" ที่ใช้แยกเครื่อง sf_credit ที่จ่ายแล้ว/ยังไม่จ่ายอยู่แล้ว (เช่นใน
   `v_sf_due.amount_due`) ยัดค่าเข้าไปตอนตั้งราคาจะทำให้สัญญาณนี้ผิดตั้งแต่เครื่องยังไม่ได้ขาย
2. **เพิ่มคอลัมน์ `sale_price` แยกจาก `list_price`, ลงต้นทุนอัตโนมัติตอนขายสด** ← เลือกอันนี้

## การตัดสินใจ

- `device_units.list_price` **คงความหมายเดิม** = ราคาป้าย SF = หนี้ที่ร้านต้องจ่ายคืน (ไม่ใช่ราคาขาย)
- เพิ่ม `device_units.sale_price` = ราคาที่ร้านตั้งขาย ตั้งได้ตอนรับบิล SF หรือแก้ทีหลังที่หน้าสต็อก และแก้ได้
  อีกทีตอนขายจริงใน POS · `null` = ใช้ `list_price` แทน (เครื่องซื้อขาด/ฝากเข้าไม่ต้องใช้ เพราะ `list_price`
  คือราคาขายอยู่แล้ว)
- ขายสดเครื่อง `sf_credit` ผ่าน `rpc_create_sale`: ระบบลง `cost = list_price` และประทับ `sf_paid_full_at`
  ให้อัตโนมัติในสเตทเมนต์เดียวกับที่เปลี่ยน `status = 'sold'` — สอดคล้องกับความจริงที่ว่าขายสดคือการจ่ายคืน SF
  เต็มจำนวนทันที
- **ถอดวันครบกำหนดออกทั้งระบบ**: `sf_orders.due_date` (คอลัมน์), `v_sf_due.days_left`, ฟอร์มกรอกวันครบกำหนด
  ที่หน้าสต็อก — ยืนยันกับ production ก่อนลบว่า `sf_orders` มี 0 แถว จึงกระทบข้อมูลจริง 0 แถว

## ผลที่ยอมรับ

- `v_sf_due.amount_due` ใช้ filter `sf_paid_full_at is null` เหมือนเดิม แต่ตอนนี้ค่าจะเปลี่ยนจริงเป็นครั้งแรก
  (เดิม `sf_paid_full_at` เป็น null เสมอ) — เครื่องที่ขายสดไปแล้วจะหลุดออกจากยอดค้างกับ SF ถูกต้องตามที่ควรเป็น
- บิล SF ที่ยังไม่จบเหลือแค่ "เหลือ N เครื่อง" ไม่มีการเรียงหรือเตือนตามวัน — ถ้า SF เริ่มส่งใบแจ้งหนี้ที่มีกำหนด
  จริงในอนาคต ต้องออกแบบใหม่ ไม่ใช่กู้คอลัมน์เดิมกลับมา
