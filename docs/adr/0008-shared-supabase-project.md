# 0008 — อยู่ร่วมโปรเจกต์ Supabase กับ DailyGold ใน schema `public` เดียวกัน

- **สถานะ:** ตัดสินใจแล้ว
- **วันที่:** 2026-08-05

## บริบท

Ucom POS ไม่ได้มีโปรเจกต์ Supabase ของตัวเอง แต่ต้องไปอยู่ในโปรเจกต์ `DailyGold & Ucom`
(`bihgcdceovfettoxmgme`, region `ap-southeast-1`, Postgres 17) ร่วมกับแอปอีกตัวชื่อ DailyGold

**เหตุผลที่ต้องแชร์ไม่ใช่ความชอบ แต่เป็นข้อจำกัดของแพลน** — org `piyapathongron-art` อยู่บน
free plan ซึ่งเปิด active project ได้สูงสุด 2 อัน (paused project ไม่นับ) ตอนนี้เต็มแล้วด้วย
`jobTracking` และ `DailyGold & Ucom` การให้ Ucom มีโปรเจกต์ของตัวเองแปลว่าต้อง pause งานอื่นทิ้ง
หรือขึ้น Pro plan

สำรวจโปรเจกต์ปลายทางแล้ว ณ วันที่ตัดสินใจ:

| ที่ | มีอะไร |
|---|---|
| `public` | ตารางเดียว — `display_settings` (0 แถว) เก็บราคาทอง/รูปโปรโมชั่นของ DailyGold |
| `auth.users` | **0 แถว** — ยังไม่มีผู้ใช้ของแอปไหนเลย |

มีโปรเจกต์เก่าชื่อ `ucom-pos` (`ulkzpawfaugzcfmnsszj`, สร้าง 17 มิ.ย. 2026) ถูก pause ค้างไว้
เจ้าของยืนยันว่าว่างเปล่า — **ปล่อยให้ pause ต่อไป ไม่ใช้ ไม่แตะ**

## การตัดสินใจ

**ทุกตารางของ POS อยู่ใน `public` ของโปรเจกต์ `bihgcdceovfettoxmgme` ใช้ชื่อตารางตามที่ออกแบบไว้
ไม่มี prefix**

## ทางเลือกที่ไม่เลือก

| ทาง | ทำไมไม่เอา |
|---|---|
| สร้าง schema `pos` แยกจาก `public` | ตัดปัญหาชื่อชนถาวรได้ด้วยต้นทุนต่ำ (~20 บรรทัด grant + `db.schema` ใน client + กด expose schema ใน dashboard) **เป็นทางที่แนะนำตอนเสนอ แต่เจ้าของเลือกไม่เอา** — ปัจจุบันยังไม่มีชื่อชนจริงสักตัว จึงยอมรับความเรียบง่ายแทน |
| กู้โปรเจกต์ `ucom-pos` มาใช้แยก | ต้อง pause `jobTracking` ทิ้งเพื่อคืน slot ให้ free plan — ไม่คุ้ม |
| ขึ้น Pro plan | $25/เดือน สำหรับร้านเดียวจุดขายเดียว — เกินความจำเป็นตอนนี้ |
| "แชร์แค่ Auth ไม่แชร์ข้อมูล" | **ทำไม่ได้** — `auth.users` เป็น schema กลางของโปรเจกต์ แชร์เสมอไม่ว่าจะเลือกทางไหน แยกได้แค่ระดับ data schema เท่านั้น |

## ผลที่ยอมรับ

- **ชื่อตารางใน `public` เป็นทรัพยากรร่วม** ชื่ออย่าง `products` `sales` `expenses` `categories`
  ร้านทองก็ใช้ได้เหมือนกัน DailyGold ถูกพัฒนาคนละ session ที่ไม่มี context ของงานนี้ →
  **ใครก็ตามที่จะเพิ่มตารางในโปรเจกต์นี้ต้อง `list_tables` ดูก่อนเสมอ**
  ADR ฉบับนี้คือที่ที่บันทึกข้อตกลงนั้นไว้
- **`auth.users` ใช้ร่วมกัน** — ผู้ใช้ของ DailyGold ล็อกอินที่หน้า POS แล้วได้ session ที่ถูกต้อง
  ตัวกันจริงคือตาราง `profiles`: ไม่มีแถวใน `profiles` = ไม่เห็นข้อมูลอะไรเลย
  **RLS policy ทุกอันต้องตรวจผ่าน `profiles` ห้ามเช็คแค่ `auth.role() = 'authenticated'`**
  (ดู ADR 0006 เรื่อง username → `xxx@ucom.local`)
- โควตา free plan ใช้ร่วมกันทั้งโปรเจกต์: database 500 MB, egress 5 GB/เดือน —
  ข้อมูล POS ระดับพันบิลอยู่หลักไม่กี่ MB ไม่ใช่ข้อจำกัดจริง
- **free plan pause โปรเจกต์เมื่อไม่มี query 7 วัน** — ตอนร้านใช้จริงทุกวันไม่โดน
  แต่ช่วง dev ที่เว้นวรรคยาวจะโดน pause ต้องกด resume เอง
- free plan **ไม่มี automated daily backup** → ดู ADR 0009
