# 0009 — ปุ่ม export JSON คือ backup ของร้าน เพราะ free plan ไม่สำรองให้

- **สถานะ:** ตัดสินใจแล้ว
- **วันที่:** 2026-08-05
- **แทนที่:** บรรทัด "ตัดออกจาก v1" ใน `docs/pos/plan-rebuild.md` ที่เคยตัด backup/restore ออก

## บริบท

แผนเดิมตัดฟีเจอร์ backup/restore ในแอปออกจาก v1 โดยให้เหตุผลว่า *"Supabase สำรองให้อยู่แล้ว"*

**เหตุผลนั้นผิด** — automated daily backup เป็นของ Pro plan ขึ้นไป โปรเจกต์นี้อยู่บน free plan
(ADR 0008) ซึ่งได้แค่ physical backup ที่ใช้ตอน pause/restore เท่านั้น กู้ข้อมูลย้อนกลับไปวันใด
วันหนึ่งไม่ได้ และถ้าโปรเจกต์ถูก pause เกิน 90 วันจะเหลือแค่ไฟล์ backup ให้โหลดไปกู้เอง

นี่คือสมุดบัญชีเล่มเดียวของร้าน ระบบเก่าที่กำลังจะเลิกใช้**มีปุ่ม backup อยู่แล้ว** —
ไฟล์ `US_POS_Backup_2026-08-04.json` ที่ใช้เป็นข้อมูลต้นทางทั้งหมดของโปรเจกต์นี้
ก็มาจากปุ่มนั้น การถอยฟีเจอร์นี้ออกคือการทำให้ระบบใหม่แย่กว่าระบบเก่าในเรื่องที่สำคัญที่สุด

## การตัดสินใจ

**หน้า settings มีปุ่มเดียว: export ทุกตารางเป็นไฟล์ JSON ดาวน์โหลด** เจ้าของร้านกดเองเมื่อไหร่ก็ได้

- อยู่ในเฟส 7 (รายงาน + รายจ่าย + วอลเล็ต) ไม่ใช่เฟสท้ายสุด — ต้องมีก่อนร้านเริ่มใช้จริง
- เจ้าของเท่านั้นที่กดได้ (มีต้นทุนกับกำไรอยู่ในไฟล์)
- **ไม่ทำ restore ในแอป** — กู้คืนเป็นงานที่เกิดไม่กี่ครั้งในชีวิต ทำผ่าน SQL ตอนนั้นได้
  ปุ่ม restore ที่กดผิดแล้วทับข้อมูลจริงอันตรายกว่าประโยชน์ที่ได้

## ผลที่ยอมรับ

- **backup เป็น manual** ถ้าเจ้าของร้านไม่กด ก็ไม่มี backup — ยอมรับ เพราะเป็นพฤติกรรมเดิมที่เขาทำอยู่แล้ว
  และการทำ scheduled dump ต้องมีที่เก็บนอกระบบ ซึ่งเกินขอบเขต v1
- ไฟล์ที่ได้ **ไม่ใช่รูปแบบเดียวกับ schema v1.1.5 ของระบบเก่า** — เป็น dump ของ schema ใหม่ตรงๆ
- ถ้าวันหนึ่งขึ้น Pro plan ปุ่มนี้ยังมีประโยชน์อยู่ (เอาไฟล์ออกนอก Supabase ได้) ไม่ต้องรื้อทิ้ง
