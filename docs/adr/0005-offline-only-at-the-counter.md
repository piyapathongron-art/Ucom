# 0005 — ทำงานออฟไลน์เฉพาะหน้าขาย

- **สถานะ:** ตัดสินใจแล้ว
- **วันที่:** 2026-08-05

## บริบท

ระบบเดิมเก็บทุกอย่างใน localStorage — เน็ตหลุด ไฟดับ router พัง ก็ยังขายของได้ ระบบใหม่ทุกครั้งที่กดขายต้องยิงไป Supabase เน็ตหลุดหนึ่งครั้ง = ลูกค้ายืนรอหน้าเคาน์เตอร์แล้วกดอะไรไม่ได้เลย

นี่คือความสามารถที่ระบบเดิมมีอยู่แล้วและกำลังจะหายไปจากการย้าย ไม่ใช่ฟีเจอร์ใหม่

## ข้อเท็จจริงที่ทำให้ตัดสินใจได้

- **จุดขายจุดเดียว หนึ่งเครื่อง** — ไม่มีสองเครื่องขายพร้อมกัน จึงไม่มีทางที่สองคนจะขาย IMEI เดียวกันหรือขายของชิ้นสุดท้ายพร้อมกัน **ปัญหา conflict ตอน sync ไม่มีอยู่จริงในร้านนี้**
- **เน็ตหลุดไม่บ่อย** — เจ้าของร้านยืนยันเอง

## ทางเลือกที่ชั่ง

1. **ออนไลน์อย่างเดียว** — โค้ดน้อยสุด แต่ถอยหลังจากของเดิมที่ทำได้อยู่แล้ว
2. **offline-first เต็มรูป** ทุกหน้าจอ — ต้องแก้ conflict ทุกตาราง เพิ่มงานเกือบเท่าตัว และแก้ปัญหาที่ร้านนี้ไม่มี
3. **กันเฉพาะจุดที่ห้ามพัง** ← เลือกอันนี้

## การตัดสินใจ

หน้าขายหน้าเดียวทำงานออฟไลน์ได้: แคตตาล็อกสินค้าและเครื่องแคชไว้ในเครื่อง บิลที่ปิดตอนออฟไลน์เข้าคิวในเครื่องแล้วส่งอัตโนมัติเมื่อเน็ตกลับมา

หน้ารายงาน / สต็อก / งานซ่อม / ตั้งค่า ออฟไลน์ = ใช้ไม่ได้ ยอมรับได้เพราะไม่มีลูกค้ายืนรอ

**จัดคิว offline เป็นงานชิ้นสุดท้ายของ v1** — ระบบใช้งานได้เต็มก่อน แล้วค่อยใส่เกราะ ถ้าอยากปล่อยของก่อนก็ปล่อยได้โดยไม่ต้องรอชิ้นนี้

## ผลที่ยอมรับ

- **ถ้าวันหนึ่งมีจุดขายที่สอง ข้อตัดสินใจนี้ใช้ไม่ได้ทันที** ต้องกลับมาทบทวนเรื่อง conflict ก่อนเพิ่มเครื่อง — เขียนไว้ตรงนี้เพราะเป็นเงื่อนไขที่มองไม่เห็นจากในโค้ด
- บิลที่ค้างคิวยังไม่ส่ง จะยังไม่โผล่ในรายงาน — ต้องมีตัวบอกสถานะให้คนขายเห็นว่ามีบิลค้างกี่ใบ
