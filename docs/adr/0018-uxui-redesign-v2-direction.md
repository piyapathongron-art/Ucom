# 0018 — Redesign รอบสอง: เพิ่มสี accent 1 สี + เปิดให้รื้อ flow ได้ทีละหน้า

- **สถานะ:** ตัดสินใจแล้ว · **mockup อนุมัติแล้ว 2026-08-16** — ยังไม่ลงมือแก้โค้ดจริง (รอแผน rollout แยก)
- **วันที่:** 2026-08-16
- **สืบเนื่องจาก:** ADR 0015 (superseded บางส่วน — ดูหัวข้อ "สืบทอด/แทนที่")

## บริบท

ADR 0015 ถูกทำจริงและ deploy ลง production pages แล้ว (branch `design/main`, commit `3a370e4`
"style: port ucom uxui system to production pages" และ `e9e11c1` "feat: add paginated ledgers
and POS checkout rail" — มาจาก prototype `codex/ucom-uxui-pages`). เจ้าของร้านดูของจริงแล้ว
**ไม่ถูกใจ** ผลลัพธ์ และสั่งให้ redesign ใหม่ทั้งหมด โดยไม่ต้องอิงของเดิมเป็นตัวอย่าง — ทั้ง
สไตล์ภาพและ flow การใช้งาน

เกรดจาก grilling session (2026-08-16, 3 รอบ): จุดที่น่าจะเป็นสาเหตุคือ ADR 0015 เขียนไว้ตรงๆ ว่า
**"ไม่มีสี accent สำหรับตัวเลขสำคัญ"** โดยตั้งใจ — ยอด/ปุ่มสำคัญเด่นด้วยขนาด/น้ำหนัก/เส้นคั่นเท่านั้น
ผลคือหน้าจอทั้งแอปดู flat ไม่มีจุดโฟกัสที่ตาจับได้ทันที ซึ่งขัดกับความคาดหวังทั่วไปของ UI ที่มี CTA
เด่นชัด

## ทางเลือกที่ชั่ง (สไตล์ภาพ)

ค้นด้วย ui-ux-pro-max (styles/typography/color domains) โดยยึด product type = POS ร้านมือถือ,
staff เร่งขายหน้าร้าน + owner ดู report:

1. **Operational Ledger 2.0** — วิวัฒนาการจาก ADR 0015: คงตาราง/เงิน mono tabular, IBM Plex Sans
   Thai, ความหนาแน่นสูง แต่**เพิ่มสี accent 1 สี**สำหรับปุ่มหลัก/สถานะที่ต้องลงมือ แทนที่จะพึ่ง
   ขนาด/น้ำหนักอย่างเดียว · โทน navy/ink neutrals + gold/amber accent (banking-finance palette)
2. **Modular Bento Ops** — การ์ด/tile สไตล์ Apple มุมโค้งมน เงานุ่ม เหมาะกับหน้า owner
   (report/expenses) ที่เป็น dashboard แต่หน้า staff (POS/stock) ที่ต้องเร็วอาจรกกว่าตารางเดิม
3. **Minimal Swiss Console** — ขาวดำล้วน มุมเหลี่ยม ไม่มี decoration, ความหนาแน่นสูงสุด, ไวสุด,
   WCAG AAA — ดูเป็นเครื่องมือมากกว่าโปรดักต์ อาจแข็งไปสำหรับ owner-facing

## การตัดสินใจ

**เลือกทิศทาง 1 — Operational Ledger 2.0**

แก้จุดที่ ADR 0015 เขียนไว้ว่าเป็นความตั้งใจ (zero accent) โดยตรง โดยไม่ทิ้งฐานที่ยังใช้ได้จริง
(ความหนาแน่น, mono tabular, IBM Plex Sans Thai, breakpoint `md` เดียว) — ความเสี่ยงต่ำกว่า B/C
ที่เปลี่ยนบุคลิกทั้งระบบ

### สืบทอด/แทนที่จาก ADR 0015

**คงไว้:** IBM Plex Sans Thai + IBM Plex Mono, `tabular-nums` สำหรับเงิน/จำนวนในตาราง, ตาราง↔การ์ด
ที่ breakpoint `md` เดียว, ไม่มี dark mode, ไม่เพิ่ม UI dependency

**แทนที่:** กติกา "ไม่มีสี accent" → **มี accent 1 สี** สำหรับ primary CTA + สถานะที่ต้องลงมือ
(ของเดิมให้ 3 สีสถานะ warning/error/success อยู่แล้วซึ่งยังใช้ต่อได้ — accent ใหม่นี้คือสีที่ 4
เฉพาะ "การกระทำหลัก" ไม่ทับความหมายกับสถานะ)

**เปิดใหม่:** อนุญาตให้ **flow เปลี่ยนได้ทีละหน้า** ไม่ใช่แค่ visual — ต่างจาก ADR 0015 ที่ fix
โครงสร้างหน้าเดิมไว้แล้วเปลี่ยนแค่ CSS/responsive · `data-testid` และโครงสร้าง e2e ไม่ใช่ข้อจำกัด
ระหว่างขั้น mockup (ตัดสินใจใหม่ตอนหน้านั้นจะลงโค้ดจริง)

### ขอบเขตของรอบนี้

Deliverable คือ **static mockup (Claude Artifact)** สำหรับ `/pos`, `/stock`, `/report` เท่านั้น —
ยังไม่แตะโค้ด production ครอบคลุมทั้ง UI pattern ที่แอปมี (staff เร่งขาย, responsive ตาราง,
owner-analytics) พอให้ตัดสินใจทิศทางได้ก่อนวางแผน rollout ทีละหน้าใน production ในรอบถัดไป

### ขอบเขต mockup ที่ทำจริง (ขยายจากแผนเดิม 3 หน้า → ครบ 8 หน้าที่มี UI)

แผนเดิมกำหนดแค่ `/pos` `/stock` `/report` เป็นตัวอย่างทิศทาง แต่ระหว่างรีวิว เจ้าของร้านขอให้ทำ
ครบทุกหน้าที่มี UI จริง (ไม่รวม `page.tsx` root ที่ redirect เฉยๆ) เพราะกำลังตัดสินใจทั้งระบบ:
`/pos` `/stock` `/report` `/close-day` `/repairs` `/sf-commissions` `/login` `/settings` — รวม 8
mockup อนุมัติแล้วทั้งหมด

### รายละเอียดที่เคาะเพิ่มระหว่างรีวิว mockup (ผูกกับ flow ไม่ใช่แค่สี — ตาม "เปิดใหม่" ด้านบน)

- **`/pos`:** ไม่มีช่องรูปสินค้า (ระบบไม่รับรูป) · ปุ่มเครื่อง SF เหลือแค่ label เฉย ๆ "ผ่อน SF" /
  "ขายสด" ไม่โชว์ตัวเลขในปุ่ม · ส่วนลดทำได้ 2 ระดับ — รายชิ้น (ต่อรายการในตะกร้า) และทั้งบิล
  (แถวสรุป) · ช่องทางชำระตัดบัตรออก เหลือ เงินสด/โอน เท่านั้น (ระบบยังไม่รองรับบัตรจริง)
- **`/stock`:** ตัดมิติ SF/ซื้อขาด และสถานะผ่อน/ซ่อมออกจากหน้านี้ทั้งหมด — ขอบเขตคือจัดการ
  **จำนวนคงเหลือ (ปุ่ม +/−) กับราคาขายเท่านั้น** ไม่ผูกกับ workflow ผ่อน SF หรือซ่อม
- **`/report`:** ตัด KPI ที่ไม่ใช่แกนหลักออก (คอมมิชชั่น SF สะสม, เงินสดปิดร้าน) เหลือ **ยอดขาย
  กับกำไร** เป็น KPI หลักของเจ้าของร้าน · กราฟอยู่ในหน้านี้อยู่แล้วซึ่งเป็นหน้า owner-only
  (nav ฝั่ง staff ไม่มีเมนูรายงานเลย) — ไม่ต้องซ่อนเพิ่ม
- **`/close-day`:** เพิ่มขอบเขตใหม่ที่ ADR 0014 ไม่ได้ครอบคลุม — มีช่องกรอก **รายรับนอกบิล**
  และ **รายจ่ายประจำวัน** (เช่น ค่าเก็บขยะ) แต่ละรายการมีช่องหมายเหตุ + **dropdown เลือกช่องทาง
  เงินสด/โอน** — เฉพาะรายการที่เลือก "เงินสด" เท่านั้นที่ถูกบวก/ลบเข้ายอด "ที่คาดว่าจะมีในลิ้นชัก"
  ก่อนเทียบกับยอดนับจริง (รายการที่เป็น "โอน" ถูกบันทึกไว้แต่ไม่กระทบยอดเงินสด) · เพิ่มตาราง
  **บิลขายทั้งหมดของวันนั้นให้พนักงาน recheck** ก่อนกดยืนยันปิดร้าน · layout เป็น 2 คอลัมน์ 50/50
  ซ้าย = กล่องปิดร้าน (คำนวณ+ยืนยัน) ขวา = บิลวันนี้ (ขึ้นก่อน) ตามด้วยประวัติปิดร้าน
- **`/repairs`:** พนักงานเห็นแค่ค่าบริการที่เก็บลูกค้า **ไม่เห็นต้นทุนอะไหล่/กำไร** — ตรงกับ
  ADR 0010 ที่ต้นทุนงานซ่อมเป็น write-only ฝั่งพนักงาน
- **`/sf-commissions`:** พนักงานดูได้อย่างเดียว ปุ่มแก้ไขเป็นสิทธิ์เจ้าของร้านเท่านั้น ตรงกับ
  page-inventory เดิม

รายละเอียดเหล่านี้เป็น flow-level ไม่ใช่แค่ visual — บันทึกไว้ที่นี่เพราะจะเป็นสเปกตั้งต้นตอนวางแผน
rollout ลงโค้ดจริง (ขั้นตอนที่ 4 ของแผน ไม่ใช่ของ session นี้)

## ผลที่ยอมรับ

- ต้องรื้อ production pages ที่เพิ่ง deploy ไป (`3a370e4`, `e9e11c1`) อีกรอบ — ต้นทุนที่ยอมรับเพราะ
  เจ้าของร้านยืนยันชัดว่าไม่ถูกใจของเดิม ปล่อยไว้เสียหายกว่า
- flow ที่เปลี่ยนได้ทีละหน้าแปลว่า e2e spec ของหน้านั้นต้องเขียนใหม่ตอน implement จริง ไม่ใช่แก้ตาม
  testid เดิม — รับรู้ล่วงหน้า ไม่ใช่ของแถมที่ค่อยมาเจอทีหลัง
- ค่าสี accent ที่แน่นอนเคาะแล้วระหว่างสร้าง mockup: `#A9790E` (พื้นสว่าง) / `#D9A53C` (พื้นมืด) —
  จงใจเลือกโทนทองอมน้ำตาลที่แยกจากสีเตือน `#A85B00` ชัดเจน กัน CTA กับสถานะเตือนไปปนกัน
- รายละเอียด flow ใหม่ต่อหน้า (ดูหัวข้อ "รายละเอียดที่เคาะเพิ่ม" ด้านบน) ยังเป็นแค่ mockup ยัง
  ไม่ผ่านการตรวจกับ schema/RPC จริง — ตอนวางแผน rollout ต้องเช็คว่าแต่ละจุด (เช่น ส่วนลดรายชิ้น/
  ทั้งบิล, ช่องทางเงินสด/โอนของรายรับ-รายจ่ายนอกบิล) มี field/ตารางรองรับหรือยัง ถ้ายังไม่มีคือ
  งาน schema เพิ่มเติมที่ไม่อยู่ใน ADR นี้
