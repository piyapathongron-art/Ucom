# 0014 — หน้าปิดร้านนับ "เงินในลิ้นชัก" ไม่ใช่ "ยอดขาย"

## บริบท

พนักงานต้องส่งเงินให้เจ้าของร้านทุกวัน ตอนนี้ไม่มีหน้าจอไหนตอบได้ว่า
**"วันนี้ในลิ้นชักต้องมีเท่าไหร่"** — `/report` ตอบเรื่องกำไรและปิดตายที่ owner
(`pos_is_owner()` ฝังอยู่ใน `v_report_entries` เอง) พนักงานอ่านไม่ได้แม้แต่แถวเดียว

ตรวจ policy บน prod แล้ว: `sales`, `sale_items`, `expenses`, `device_units`
ทุกตัวมี policy เดียวคือ `pos_is_owner()` — พนักงานอ่านตรงไม่ได้ทั้งหมด

คำถามที่หน้านี้ต้องตอบต่างจากคำถามที่ `/report` ตอบ:

| | `/report` | หน้าปิดร้าน |
|---|---|---|
| ตอบคำถาม | ร้านกำไรเท่าไหร่ | ในลิ้นชักต้องมีเท่าไหร่ |
| บิลปิดงานซ่อม | **ตัดออก**จากยอดขาย (ท่อ 2 เป็นเจ้าของ) | **นับ** — เงินเข้าลิ้นชักจริง |
| ค่าคอม SF+ | นับเป็นรายได้ | **ไม่นับ** — ไม่ใช่เงินสด และมาทีหลังเป็นเงินโอน |
| เงินโอน | นับเป็นรายได้ | นับเป็นข้อมูล แต่ไม่อยู่ในยอดที่ต้องส่ง |
| ต้นทุน/กำไร | แสดง | **ห้ามมีอยู่ใน view เลย** (กฎข้อ 4) |

ADR 0013 บอกว่านิยามเงินอยู่ที่ `v_report_entries` ที่เดียว — ถ้าอ่านตรงตัวแล้วบังคับให้
หน้าปิดร้าน sum ต่อจาก `v_report_entries` ตัวเลขจะ**ผิด**สำหรับงานที่มันต้องทำ
เพราะบิลซ่อมถูกตัดออกไปแล้ว

## ทางเลือก

1. **ให้หน้าปิดร้านอ่านจาก `v_report_entries`** — นิยามเงินยังอยู่ที่เดียวตาม ADR 0013
   แต่ต้องเปิด view ที่มีคอลัมน์กำไรให้พนักงานอ่าน (พังกฎข้อ 4) และยอดที่ได้ยัง
   ขาดบิลซ่อมอยู่ดี
2. **view ชุดใหม่ที่ gate ด้วย `pos_is_member()` ไม่มีคอลัมน์ต้นทุน/กำไร** และประกาศชัดว่า
   นี่ไม่ใช่ view รายงานเงิน
3. เปิด RLS ให้พนักงานอ่าน `sales`/`expenses` ตรงๆ — พนักงานเห็นทุกคอลัมน์รวมถึงบิลย้อนหลังทั้งหมด

## การตัดสินใจ

**เลือกทางที่ 2** และเขียนขอบเขตของ ADR 0013 ให้ชัดขึ้น:

> ADR 0013 ครอบ **นิยาม "เงินของร้าน"** (รายได้ ต้นทุน กำไร) — `v_report_entries` ยังเป็นที่เดียว
> ที่นิยามมัน · หน้าปิดร้านไม่ได้ถามคำถามนั้น มันถาม **"เงินสดที่ผ่านมือพนักงาน"**
> ซึ่งเป็นปริมาณคนละตัว view ชุด `v_close_day_*` จึงนับบิลทุกใบตาม `payment_method`
> โดยไม่สนใจว่าบิลนั้นเป็นยอดขายหรือรายได้งานซ่อม

**ตัวเลขที่หน้านี้ยึด:**

```
ยอดที่ต้องส่ง = เงินสดที่รับทั้งวัน − รายจ่ายที่จ่ายด้วยเงินสดในวันนั้น
```

เงินโอนไม่อยู่ในสมการนี้ เพราะเข้าบัญชีร้านไปแล้ว พนักงานไม่ได้ถือ

**สิ่งที่บันทึกลงตาราง `day_closings`:** เฉพาะข้อเท็จจริงที่ derive ไม่ได้ —
วันที่ปิด · ปิดกี่โมง · ปิดโดยใคร · **เงินสดที่นับได้จริงในลิ้นชัก** · หมายเหตุ

**สิ่งที่ห้ามบันทึกลงไป:** ยอดขาย ยอดรายจ่าย ยอดที่ควรมี ส่วนต่าง — ทั้งหมดคำนวณสด
ตาม ADR 0004 ถ้าเก็บไว้แล้ววันหนึ่งไม่ตรงกับผลรวมจริง จะไม่มีใครรู้ว่าอันไหนถูก

**คอลัมน์ใหม่ `expenses.paid_from`** (`cash` / `transfer` / null) — จำเป็นเพราะสมการข้างบน
ต้องแยกให้ออกว่ารายจ่ายก้อนไหนหยิบจากลิ้นชัก แถวเดิม 53 แถวปล่อยเป็น null
(ไม่หักออกจากยอดส่งย้อนหลัง ซึ่งถูกต้อง — ตอนนั้นไม่มีการปิดร้าน)

## ผลที่ยอมรับ

- มี view ที่ให้ตัวเลข "ยอดขายวันนี้" อีกชุดหนึ่งที่**ไม่เท่ากับ** `sale_revenue` ใน `/report`
  โดยตั้งใจ — ทุก view ในชุดนี้ต้องมี comment หัวไฟล์บอกว่ามันตอบคำถามอะไร
  ไม่งั้นคนถัดไปจะคิดว่าเจอบั๊ก
- พนักงานเห็นยอดขายรวมของวัน (แต่ไม่เห็นต้นทุนและกำไร) — รับได้ ร้านเดียวคนสองคน
- ถ้าเจ้าของร้านแก้รายจ่ายย้อนหลัง ส่วนต่างเงินขาด/เกินของวันนั้นขยับตาม —
  ตั้งใจ ตัวเลขที่ถูกคือตัวเลขล่าสุดเสมอ
- ค่าคอม SF+ ไม่โผล่ในหน้านี้เลย แม้แต่ตอนที่เฟส "รอค่าคอม" มาถึง — ค่าคอมมาเป็น
  เงินโอนเสมอ จึงไม่เคยอยู่ในลิ้นชัก
