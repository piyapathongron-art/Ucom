# 0011 — อะไหล่ของงานที่ลูกค้าทิ้ง ลงที่ `repair_profit` ไม่ใช่ `expense`

- **สถานะ:** ตัดสินใจแล้ว
- **วันที่:** 2026-08-10
- **ปิดข้อค้างของ:** ADR 0010 หัวข้อ "ที่ยังค้าง"

## บริบท

ADR 0003 บอกไว้ว่าอะไหล่ที่จ่ายเงินไปแล้วของงานที่ลูกค้าไม่มารับ **ตกเป็นค่าใช้จ่ายร้านในวันที่ตัดทิ้ง** แต่ pipe 2 ของรายงานกรอง `status = 'collected'` อย่างเดียว งาน `abandoned` จึงหายไปทั้งก้อน — เงินที่จ่ายค่าอะไหล่ไปแล้วไม่โผล่ที่ไหนเลย กำไรอ่านได้สูงเกินจริงตลอดไป

เฟส 6 เป็นเฟสแรกที่กด `abandoned` ได้ ปัญหาเลยเพิ่งจับต้องได้

ตอนเปิดของจริงมาอ่านเจอว่า premise ที่ ADR 0010 เขียนไว้ผิด 3 จุด:

1. **ไม่มี view ชื่อ `v_pos_pl` ในสคีมา** ของจริงคือ `v_monthly_report` (`20260805120100_pos_views.sql:80`) — ADR 0010 อ้างชื่อที่ไม่มีอยู่
2. **"นับต้นทุนที่วันไหน" ไม่ใช่ข้อค้าง** ADR 0003 เคาะไปแล้วว่า "ในวันที่ตัดทิ้ง"
3. **ไม่ต้องเพิ่มคอลัมน์เก็บวันตัดทิ้ง** `closed_at` มีอยู่แล้วบน `repair_jobs` และ constraint `repair_collected_needs_closed_at` บังคับเฉพาะตอน `collected` เท่านั้น — `rpc_set_repair_status` แค่ไม่เคย set ให้ตอน abandon

ข้อค้างจริงที่เหลือจึงแคบกว่าที่ ADR 0010 คิด: **ต้นทุนก้อนนี้ควรโผล่ที่คอลัมน์ไหนของรายงาน**

## การตัดสินใจ

**ขยาย pipe 2 ให้รับงาน `abandoned` ที่มี `part_cost` เข้ามาด้วย โดยให้ revenue = 0 และหัก `part_cost` ตามปกติ** เดือนที่ตัดทิ้งจะเห็น `repair_profit` ติดลบ ส่วนคอลัมน์ `expense` ไม่ขยับ

พ่วงอีก 2 อย่างที่จำเป็นต่อการนี้:

- `rpc_set_repair_status` stamp `closed_at = now()` ตอนตั้ง `abandoned` (สถานะปลายทางออกไม่ได้ตาม ADR 0010 ข้อ 2 จึงเขียนทับไม่ได้อยู่แล้ว)
- backfill แถว `abandoned` เก่าที่ `closed_at` ยังว่าง ด้วย `coalesce(part_paid_at, received_at)`

งานที่ทิ้งก่อนซื้ออะไหล่ (`part_cost is null`) **ไม่เข้ารายงาน** — ไม่มีเงินเคลื่อนไหว การใส่เข้าไปได้แค่เปิดแถวเดือนเปล่าๆ

`net_profit` ออกมาเท่ากันไม่ว่าจะเลือกทางไหน (`sum(repair_profit) − sum(expense)`) ที่ต่างกันจริงคือเจ้าของร้านเห็นมันที่ช่องไหน และกฎข้อไหนถูกรักษาไว้

## ทางที่ไม่เลือก

**เพิ่ม pipe 5 ยิงเข้าช่อง `expense`** — ตรงตัวอักษร ADR 0003 ที่ใช้คำว่า "ค่าใช้จ่ายร้าน" มากกว่า แต่:

- ชนกับหัวใจของ ADR 0003 ที่ชื่อเรื่องคือ *repair jobs own their cost* — ต้นทุนอะไหล่ไม่เคยเป็นรายจ่ายลอยๆ มันผูกกับงาน
- pipe 4 เขียนคอมเมนต์กำกับไว้ตรงๆ ว่า `shop expenses. Repair parts are NOT here.`
- ทำให้ช่อง `expense` ผสมของสองชนิด: รายจ่ายจริงจากตาราง `expenses` กับต้นทุนที่ derive มาจากงานซ่อม — อ่านแล้วกระทบยอดไม่ตรงกับตาราง `expenses`

คำว่า "ตกเป็นค่าใช้จ่ายร้าน" ใน ADR 0003 อ่านเป็นเจตนาเชิงเศรษฐกิจ (ร้านกินต้นทุนก้อนนี้เอง) ไม่ใช่คำสั่งว่าต้องลงคอลัมน์ไหน

**ปล่อยไว้ให้เฟสรายงานแก้** (ตามที่ ADR 0010 เขียนไว้) — หน้า `/report` ยังเป็น stub จริง แต่ view พังตั้งแต่วันนี้ไม่ว่าจะมี UI อ่านหรือไม่ และบริบทกำลังอยู่ในมือ

## ผลที่ยอมรับ

- เดือนที่มีแต่งานทิ้งจะเห็น `repair_profit` ติดลบโดยไม่มี `repair_revenue` คู่กัน — ถูกต้องแล้ว แต่หน้ารายงานต้องไม่ format ให้ดูเหมือน error
- `repair_profit` ไม่ใช่ "กำไรจากงานที่ปิดขาย" อีกต่อไป แต่เป็น "ผลรวมเงินจากงานซ่อมที่ปิดในเดือนนั้น" — เฟสรายงานต้องตั้งชื่อหัวคอลัมน์ให้ตรงความหมายนี้
